# SAR Ship Detector

Система обнаружения кораблей на SAR-изображениях (Synthetic Aperture Radar) с веб-интерфейсом и поддержкой двух моделей детекции: YOLO и Faster R-CNN.

## Архитектура

Система состоит из следующих компонентов:

### Backend (FastAPI)
- **app/main.py** - основное приложение FastAPI
- REST API для управления задачами (загрузка изображений, запуск детекции, получение результатов)
- Асинхронная обработка задач с использованием Redis и RQ (Redis Queue)
- Фоновый процесс очистки старых задач
- Статическое обслуживание frontend-файлов

### Worker
- Отдельный контейнер для выполнения инференса моделей
- Изолирован от веб-сервера для лучшей производительности и масштабируемости
- Использует ту же кодовую базу, что и backend

### Frontend
- Одностраничное приложение на чистом HTML/CSS/JS
- Интерфейс для загрузки SAR-изображений (GeoTIFF)
- Настройка параметров детекции:
  - Тип модели (YOLO26s или Faster R-CNN)
  - Поляризация (VV, VH, HH, HV)
  - Формат входных данных (Byte, dB, Linear)
  - Размер окна и перекрытия
  - Пороговые значения и NMS
  - Улучшение контраста (процентильное растяжение, gamma, CLAHE)
  - TTL для автоматического удаления задач
- Отображение списка задач и их статусов
- Предварительный просмотр исходного изображения и результата детекции
- Визуализация обнаруженных кораблей на превью с цветовой шкалой уверенности

### Модели
- **YOLO26s** - легкая модель для реального времени
- **Faster R-CNN** - более точная модель с ResNet50 backbone
- Обе модели адаптированы для работы с одноканальными SAR-изображениями
- Веса моделей хранятся в директории `models/`

### Инференс
- Слайдинг-окно с настраиваемым перекрытием
- Предобработка патчей:
  - Конвертация форматов (byte, dB, linear)
  - Интерполяция меньших окон до размера обучения модели (800x800)
  - Улучшение контраста (процентильное растяжение, gamma-коррекция, CLAHE)
- Выполнение детекции на каждом патче
- Глобальное NMS (Non-Maximum Suppression) для удаления дубликатов
- Формирование результата в формате GeoJSON с географическими координатами
- Наложение обнаруженных объектов на превью изображение

## Возможности

### Поддерживаемые форматы входных данных
- GeoTIFF (.tif, .tiff) - одноканальные SAR-изображения
- Три форматаinterpretation:
  - Byte 0-255 (стандартный экспорт из SNAP/QGIS)
  - dB sigma0
  - Linear sigma0

### Настройки детекции
- **Размер окна**: 192, 224, 448, 512, 800, 1024 пикселей
- **Перекрытие**: 0-75% с шагом 5%
- **Порог уверенности**: 0.05-0.95
- **NMS IoU**: 0.1-0.7
- **Размер целевого изображения для интерполяции**: 512 или 800 пикселей
- **Поляризация**: VV, VH, HH, HV
- **Улучшение контраста**:
  - Метод: процентильное растяжение или min-max
  - Процентильный диапазон: настраиваемый
  - Gamma-коррекция: 0.3-3.0
  - CLAHE (Contrast Limited Adaptive Histogram Equalization)

### Управление задачами
- Загрузка больших файлов с потоковой передачей и отображением прогресса
- Очередь задач с приоритетом FIFO
- Статусы задач: queued, running, done, error
- Автоматическое удаление задач через настраиваемое время (TTL)
- Возможность ручного удаления задач
- Обновление TTL задачи в реальном времени

### Результаты
- GeoJSON-файл с обнаруженными объектами (координаты, уверенность, размеры боксов)
- Превью исходного изображения с примененным улучшением контраста
- Превью результата с наложенными bounding boxes и цветовой шкалой уверенности
- Счетчик обнаруженных объектов

## Технологический стек

- **Backend**: Python 3.9+, FastAPI, Uvicorn
- **Очередь задач**: Redis, RQ (Redis Queue)
- **Frontend**: HTML5, CSS3, Vanilla JavaScript (ES6+)
- **Модели детекции**: 
  - YOLO (ultralytics)
  - Faster R-CNN (PyTorch, torchvision)
- **Обработка изображений**: 
  - RasterIO (чтение GeoTIFF)
  - OpenCV (предобработка, CLAHE)
  - PIL/Pillow (создание превью)
  - NumPy (数值计算)
- **Контейнеризация**: Docker, Docker Compose
- **База данных**: Redis (для очереди и метаданных задач)

## Запуск

### Предварительные требования
- Docker и Docker Compose
- Минимум 4 ГБ RAM (рекомендуется 8 ГБ+ для больших изображений)

### Быстрый старт
```bash
# Клонировать репозиторий
git clone <repository-url>
cd webship

# Запустить все сервисы
docker-compose up --build

# Открыть в браузере
http://localhost:8000
```

### Переменные окружения
Можно настроить через `docker-compose.yml`:
- `REDIS_URL` - URL подключения к Redis (по умолчанию: redis://redis:6379)
- `JOBS_DIR` - директория для хранения задач (по умолчанию: /jobs)
- `MODELS_DIR` - директория с моделями (по умолчанию: /models)
- `JOB_TTL_MINUTES` - время жизни задач в минутах (по умолчанию: 60, -1 = никогда)

## API endpoints

### GET `/`
- Возвращает главную страницу (index.html)

### GET `/api/jobs`
- Возвращает список всех задач с их статусами и метаданными

### POST `/api/jobs`
- Создает новую задачу детекции
- Параметры:
  - `file`: GeoTIFF изображение
  - `model_type`: 'yolo' или 'fasterrcnn'
  - `polarization`: 'VV', 'VH', 'HH', 'HV'
  - `input_format`: 'byte', 'db', 'linear'
  - `window_size`: размер окна в пикселях
  - `overlap_pct`: коэффициент перекрытия (0-1)
  - `score_thresh`: порог уверенности (0-1)
  - `nms_iou`: порог NMS (0-1)
  - `ttl_minutes`: время жизни задачи (-1 = никогда)
  - Параметры контраста: `contrast_enabled`, `contrast_method`, `percentile_low`, `percentile_high`, `gamma`, `clahe`, `target_size`
- Возвращает: `{"job_id": "<uuid>"}`

### GET `/api/jobs/{job_id}/status`
- Возвращает статус задачи: `{"status": "...", "progress": ..., "message": "..."}`

### GET `/api/jobs/{job_id}/preview`
- Возвращает превью исходного изображения (PNG)

### GET `/api/jobs/{job_id}/preview_result`
- Возвращает превью результата детекции с наложенными боксами (PNG)

### GET `/api/jobs/{job_id}/result`
- Возвращает результат детекции в формате GeoJSON

### PATCH `/api/jobs/{job_id}/ttl`
- Обновляет время жизни задачи
- Тело запроса: `{"ttl_minutes": <int>}`

### DELETE `/api/jobs/{job_id}`
- Удаляет задачу и все связанные файлы

## Примечания по производительности

- Для больших изображений рекомендуется использовать размер окна 800 или меньше
- Увеличение перекрытия улучшает качество детекции на границах окон, но увеличивает время обработки
- YOLO модель значительно быстрее Faster R-CNN, но может быть менее точной на сложных сценах
- Использование CLAHE улучшает видимость кораблей на низкоконтрастных SAR-изображениях
- Система автоматически удаляет исходное изображение после загрузки для экономии места, сохраняя только результаты и превью
