# Веб-сервис детекции кораблей на SAR-изображениях

## О проекте

Веб-сервис для автоматической детекции кораблей на синтетических aperture radar (SAR) изображениях. 
Система поддерживает два метода детекции:
1. Глубокое обучение на основе модели YOLO (обученной на SAR-данных)
2. Традиционный метод CFAR (Constant False Alarm Rate) с пост-обработкой

## Архитектура

Система построена на микросервисной архитектуре с использованием контейнеризации Docker:

### Компоненты

1. **FastAPI приложение** (`app/`)
   - RESTful API для загрузки изображений и управления задачами
   - Интерфейс пользователя (статические файлы в `static/`)
   - Очередь задач через Redis и RQ (Redis Queue)
   - Механизм очистки устаревших задач

2. **Worker** (`shared/inference_jobs.py`)
   - Выполняет ресурсоемкие задачи детекции в фоне
   - Поддерживает как YOLO-модели, так и традиционные алгоритмы
   - Сохраняет результаты и промежуточные превью

3. **Redis**
   - Брокер очередей для распределения задач между приложением и воркером
   - Хранение метаданных и статусов задач

4. **Общая папка** (`shared/`)
   - `inference_jobs.py` - основная логика выполнения задач детекции
   - `traditional_detection.py` - реализация CFAR и связанных алгоритмов

5. **Модели** (`models/`)
   - Предобученные веса YOLO (`best.pt`, `bestv2.pt`)

6. **Географические данные** (`gshhg/`)
   - Shapefiles GSHHS для традиционной детекции (определение береговой линии)

### Взаимодействие

1. Пользователь загружает SAR-изображение через веб-интерфейс
2. FastAPI создает запись задачи, сохраняет изображение и отправляет задачу в очередь Redis
3. Worker получает задачу, выполняет детекцию выбранным методом
4. Результаты сохраняются в директории задачи (превью, ZIP с детекциями)
5. Пользователь может отслеживать статус задачи и скачивать результаты

## Возможности

- Загрузка SAR-изображений в различных форматах (поддерживается байтовый ввод и путь к файлу)
- Выбор между двумя методами детекции:
  - **YOLO**: глубокое обучение для высокоточной детекции
  - **Традиционный (CFAR)**: настраиваемый алгоритм с параметрами PFA, guard, train
- Настройка параметров детекции:
  - Размер окна и перекрытие для скользящего окна
  - Порог уверенности и IoU для NMS (для YOLO)
  - Параметры контрастного улучшения (процентильный stretch, CLAHE, гамма-коррекция)
  - TTL (время жизни) задачи в системе
- Предварительный просмотр исходного изображения и результата детекции
- Скачивание результатов в виде ZIP-архива с геометками детекций
- Автоматическая очистка устаревших задач
- Мониторинг статуса задач в реальном времени

## Технологический стек

- **Backend**: Python 3.9+, FastAPI
- **Очередь задач**: Redis + RQ (Redis Queue)
- **Машинное обучение**: PyTorch, Ultralytics YOLO
- **Обработка изображений**: OpenCV, NumPy
- **Frontend**: HTML5, CSS3, JavaScript (vanilla)
- **Контейнеризация**: Docker, Docker Compose
- **Геопространственные данные**: GDAL/OSGeo (через зависимости traditional_detection)

## Запуск

### Требования

- Docker и Docker Compose
- Минимум 4 ГБ RAM (рекомендуется 8 ГБ+ для YOLO-моделей)

### Инструкция

1. Клонировать репозиторий
2. Запустить сборку и контейнеры:
   ```bash
   docker-compose up --build
   ```
3. Открыть веб-интерфейс по адресу: http://localhost:8000

### Переменные окружения

Можно настроить через `.env` файл или непосредственно в `docker-compose.yml`:
- `REDIS_URL` - подключение к Redis (по умолчанию: redis://redis:6379)
- `JOBS_DIR` - директория для хранения задач (по умолчанию: /jobs)
- `MODELS_DIR` - директория с моделями (по умолчанию: /models)
- `GSHHG_SHP_PATH` - путь к shapefile GSHHS для традиционной детекции
- `JOB_TTL_MINUTES` - время жизни задачи по умолчанию (минуты)

## Использование

### Через веб-интерфейс

1. Перейдите на главную страницу
2. Нажмите "Выберите файл" и загрузите SAR-изображение
3. Выберите метод детекции (YOLO или Традиционный)
4. При необходимости настройте параметры детекции
5. Нажмите "Отправить задачу"
6. Отслеживайте статус задачи в списке задач
7. После завершения нажмите "Просмотр результата" или "Скачать результат"

### Через API

Система предоставляет RESTful API для интеграции:

- `POST /api/jobs` - создание новой задачи
- `GET /api/jobs` - получение списка всех задач
- `GET /api/jobs/{job_id}/status` - получение статуса конкретной задачи
- `GET /api/jobs/{job_id}/preview` - предварительный просмотр исходного изображения
- `GET /api/jobs/{job_id}/preview_result` - предварительный просмотр результата детекции
- `GET /api/jobs/{job_id}/result` - скачивание результата в ZIP-архиве
- `PATCH /api/jobs/{job_id}/ttl` - обновление времени жизни задачи
- `DELETE /api/jobs/{job_id}` - удаление задачи

## Примечания

- Первоначальная загрузка YOLO-модели может занять некоторое время при первом запуске
- Для традиционной детекции качество результатов сильно зависит от правильной настройки параметров CFAR
- Система оптимизирована для работы с SAR-изображениями в формате GeoTIFF и подобных
- Результаты детекции сохраняются в формате GeoJSON внутри ZIP-архива вместе с превью изображением
